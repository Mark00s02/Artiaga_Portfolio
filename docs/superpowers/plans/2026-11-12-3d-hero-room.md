# 3D Hero Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the home hero background with a live 3D dev room (character typing at a desk), mouse parallax and scroll dolly, and remove the cursor/glow-dot effects.

**Architecture:** One ES module `public/hero3d.js` builds a Three.js scene into a `<canvas>` behind the existing hero text. Pure camera math lives in `public/hero3d-math.js` (tested with `node --test`). All asset paths sit in one `ASSETS` map at the top of `hero3d.js`, so switching realistic ↔ cartoon style means swapping files, not code.

**Tech Stack:** Three.js 0.160.0 from `cdn.jsdelivr.net` via an import map (no build step); GLTFLoader, FBXLoader, RGBELoader from `three/addons`; Node 18+ `node --test` for the math.

**Spec:** `docs/superpowers/specs/2026-11-12-3d-hero-room-design.md`

## Global Constraints

- No build step, no new npm dependencies; Three.js pinned to `0.160.0` from jsDelivr.
- Assets only from `public/assets/3d/` (models, textures, hdri, character).
- No custom cursor, no cursor-following effects, no pulsing/glowing status dots anywhere on the site.
- The 2D hero renders instantly; the 3D canvas fades in only after the room has loaded.
- If WebGL is missing or any required load fails, the page looks like today minus the removed effects; no console errors that break `app.js`.
- Character files are optional at runtime: missing `character/typing.fbx` = empty chair, scene still shows.
- Render loop pauses when the hero is off-screen, the home page is not active, or the tab is hidden.

## Review Focus

- Character FBX not yet downloaded (404) → room still renders, no thrown error. (Task 3 manual check)
- Phone width (375px) → text readable over scene, no horizontal scroll, pixel ratio ≤ 1.5, no shadows. (Task 4)
- Navigating Home → Works → Home → canvas resumes, not duplicated. (Task 3)
- `prefers-reduced-motion` → no scroll dolly or parallax motion; static framed camera. (Task 2 test)
- Window resize → canvas and camera aspect update, no stretching. (Task 3)

### Task 2: Camera math (tested)

**Files:**
- Create: `public/hero3d-math.js`
- Test: `tests/hero3d-math.test.mjs`

**Interfaces:**
- Produces:
  - `scrollProgress(scrollY: number, heroHeight: number): number` → clamped 0..1
  - `cameraPose(mx: number, my: number, progress: number, reduced: boolean): {pos:[x,y,z], target:[x,y,z]}`
    where `mx,my` ∈ [-1,1] are normalised mouse coords. `REST`, `SCREEN` exported constants are the start pose and the
    pose framing the monitor; result lerps REST→SCREEN by `easeInOutCubic(progress)` and adds parallax offset
    `PARALLAX = 0.35` (world units) × (mx, my) on pos only, scaled by `(1 - progress)`. `reduced` ⇒ mx=my=0, progress=0.
  - `damp(current: number, target: number, lambda: number, dt: number): number` (frame-rate independent ease)

- [ ] **Step 1: Failing tests** in `tests/hero3d-math.test.mjs` (`node:test` + `node:assert`):
  - `scrollProgress(-10, 800) === 0`, `scrollProgress(400, 800) === 0.5`, `scrollProgress(5000, 800) === 1`, `scrollProgress(100, 0) === 0`
  - `cameraPose(0,0,0,false).pos` deep-equals `REST.pos`; `cameraPose(0,0,1,false).pos` deep-equals `SCREEN.pos`
  - `cameraPose(1,0,0,false).pos[0] - REST.pos[0]` ≈ `0.35`; `cameraPose(1,0,1,false).pos` deep-equals `SCREEN.pos`
  - `cameraPose(1,1,0.7,true)` deep-equals `cameraPose(0,0,0,false)`
  - `damp(0, 10, 5, 0) === 0`; `damp(0,10,5,1000)` ≈ `10`

- [ ] **Step 3:** Implement in `public/hero3d-math.js` (ES module, no imports). `damp` = `target + (current-target)*Math.exp(-lambda*dt)`.
